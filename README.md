# 签到打卡系统 · 高保真交互原型

覆盖移动端员工打卡与 PC 管理端的完整考勤签到原型，共 9 个可交互页面。原型用纯 HTML/CSS/JS 构建，零依赖、离线可打开；所有表单字段均标注必填性（必填/选填/条件必填/自动获取/系统生成），考勤判定规则全站统一。适用于需求评审、开发对齐与后端接口设计的输入材料。

## 快速开始

无需安装任何依赖，克隆后直接用浏览器打开入口页即可：

```bash
git clone https://github.com/chrisleehe/checkin-prototype.git
cd checkin-prototype
start index.html   # Windows（macOS 用 open index.html）
```

也可以只下载仓库后双击 `index.html`，所有页面间跳转、打卡交互、表单校验均可在本地离线完成。

## 可体验的交互

原型不是静态图，以下行为均已实现：

- **打卡状态机**：移动端首页可真实点击上/下班打卡，按钮经历"定位中 → 成功"状态流转，结果写入 `localStorage`，刷新不丢；下班完成后自动计算工时（扣除午休 1 小时）。
- **表单校验**：补卡/请假表单提交时校验必填项，缺失字段标红并给出 toast 提示；详细说明不足 10 字会被拦截。
- **条件必填联动**：PC 规则配置页中，"打卡方式"切换时自动挂载/卸载 GPS 范围、WiFi 白名单两个条件必填字段的校验。
- **审批流**：待审单可"通过/驳回"，驳回必须填写 10-100 字意见；处理后卡片状态与角标实时更新。
- **查询与筛选**：PC 记录页按部门/状态/姓名真实过滤 12 人数据，详情弹窗展示打卡定位与关联审批。

## 字段必填标注体系

全站表单统一使用五类标注，徽标样式与文案在任何页面保持一致：

| 标注 | 含义 | 校验行为 |
|---|---|---|
| 必填 | 用户必须填写 | 留空时提交被拦截并标红 |
| 选填 | 可留空 | 不影响提交 |
| 条件必填 | 依赖其他选项 | 触发条件后按必填处理 |
| 自动获取 | 系统采集 | 只读展示（时间/定位/WiFi） |
| 系统生成 | 服务端产生 | 只读展示（单号/审批流） |

两处核心表单的字段定义摘要如下，完整版见对应页面底部的字段说明表。

补卡申请（`mobile/m-apply.html`）：

| 字段 | 必填性 | 校验规则 |
|---|---|---|
| 补卡日期 | 必填 | 今日之前 30 天内的工作日 |
| 补卡时段 | 必填 | 上班 / 下班（单选） |
| 补卡时间 | 必填 | 上班卡 06:30-10:00，下班卡 15:30-23:59 |
| 事由类型 | 必填 | 5 选 1：忘打卡/交通延误/设备故障/临时外出/其他 |
| 详细说明 | 必填 | 10-200 字，带实时字数 |
| 证明附件 | 选填 | 最多 3 张，单张 ≤10MB |
| 抄送人 | 选填 | 最多 5 人 |

考勤规则配置（`pc/p-rules.html`）：

| 字段 | 必填性 | 校验规则 |
|---|---|---|
| 规则名称 | 必填 | 2-20 字，企业内唯一 |
| 适用部门 | 必填 | 至少 1 个部门，多选 |
| 工作日 / 上下班时间 | 必填 | 至少 1 个工作日；上班早于下班 |
| 迟到宽限 | 必填 | 0-30 分钟，默认 10 |
| 打卡方式 | 必填 | GPS / WiFi / 两者均可 |
| GPS 打卡范围 | 条件必填 | 打卡方式含 GPS 时必填，100-3000 米 |
| WiFi 白名单 | 条件必填 | 打卡方式含 WiFi 时至少 1 个 SSID |
| 弹性工作 / 补卡上限 / 节假日免打 | 选填 | 弹性 0-120 分钟；补卡 0-10 次/月 |

## 考勤判定规则

以默认规则"总部标准考勤"（09:00-18:00，宽限 10 分钟，GPS 500 米或办公 WiFi）为例：

1. 正常出勤：上班卡不晚于 09:10，下班卡不早于 18:00
2. 迟到：09:10 后打卡；09:30 后记严重迟到并抄送直属上级
3. 早退：工作日 18:00 前打下班卡
4. 缺卡：仅一边有卡；旷工：全天无卡且无已通过的补卡/请假
5. 外勤：GPS 不在打卡范围时记外勤，须附现场照片与事由并经审批
6. 补卡：每人每月不超过 3 次，须于次日 18:00 前提交，走直属上级 → HR 二级审批
7. 有效工时：上/下班卡间隔扣除午休 1 小时（12:00-13:00）

## 技术实现

纯静态架构，无构建工具、无外部 CDN，克隆即用：

- **共享设计系统**：`assets/styles.css` 集中管理设计令牌（青绿主色、等宽时间字体）与全部组件样式，9 个页面复用同一套类名，保证跨页一致。
- **统一数据源**：`assets/mock.js` 中的 `DB` 对象承载全部演示数据（员工、记录、规则、审批单），页面禁止散落硬编码，跨页数据天然一致。
- **API 桩层**：`assets/api.js` 暴露 `window.API`，每个函数都标注了未来真实的 HTTP 方法与路径（`// TODO: replace with fetch(...)`）。接入真实后端时，仅需将桩实现替换为真实请求，页面代码无需改动。
- **图标方案**：`assets/icons.js` 内联 Lucide SVG（46 个），离线可用且风格统一。

```
checkin-prototype/
├── index.html              # 总览入口
├── assets/
│   ├── styles.css          # 设计系统与组件库
│   ├── icons.js            # 内联 SVG 图标
│   ├── mock.js             # 统一 Mock 数据
│   ├── api.js              # API 桩层（后端接入点）
│   └── app.js              # 通用交互（导航/tab/toast/校验）
├── mobile/                 # 移动端 4 页（手机外框预览）
└── pc/                     # PC 管理端 4 页（侧栏布局）
```

## 后端对接说明

原型刻意保持了"形状即接口"的分层：`api.js` 中每个异步函数的签名、参数与返回结构均按真实 API 设计，并以 `// TODO` 注释标明对应的 HTTP 方法与路径（如 `POST /api/attendance/clock-in`）。后端按此契约实现接口后，将桩内延迟替换为 `fetch` 调用即可完成联调，前端页面零改动。
